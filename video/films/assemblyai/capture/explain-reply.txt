L43, L44 · Stop sends Terminate and waits for Termination
The socket closes immediately after sending Terminate, discarding the final Turn message that contains the last transcript, because the server sends the final transcript in a Turn message after receiving Terminate.
Fix: Send {"type":"Terminate"}, keep reading until the Termination message, then close.

L31 · Audio is PCM16 from an AudioWorklet
MediaRecorder with mimeType 'audio/ogg;codecs=opus' will throw a NotSupportedError in Chrome and Edge because Chromium browsers do not support recording Ogg Opus via MediaRecorder.
Fix: Capture with an AudioWorklet that resamples to 16 kHz and sends Int16 PCM in ~50 ms chunks (see The fix below).

L9 · Doc snippets compile
The object property uses '=' instead of ':', causing a SyntaxError when the code runs because JavaScript object literals require colons to assign values.
Fix: Use a colon: { expires_in_seconds: 60 }. Moving to the documented POST mint (L8) removes this call entirely.

L8 · Token minted on the documented endpoint
The SDK's createTemporaryToken method calls an undocumented GET endpoint, while the official temporary token endpoint is a POST request to token.assemblyai.com/v1/token.
Fix: Mint server-side with fetch('https://token.assemblyai.com/v1/token', { method: 'POST', headers: { Authorization: process.env.ASSEMBLYAI_API_KEY, 'Content-Type': 'application/json' }, body: JSON.stringify({ product: 'streaming', expires_in_seconds: 60 }) }).

L8 · Token is short-lived and streaming-only
The temporary token generated via the SDK's method cannot restrict access to only streaming, so it could be used to open other products like TTS or LLM Gateway.
Fix: Keep expires_in_seconds short (60) and turn off other products with access.

L7 · Token route runs per request
A GET route handler in Next.js 14 is prerendered by default, generating a single token at build time that expires quickly, making it useless for subsequent visitors.
Fix: Add export const dynamic = 'force-dynamic' to the token route. It stays GET, so the client needs no change.

L28 · Speech model is explicit and current
The WebSocket URL does not specify a speech_model parameter, so the server defaults to universal-3-6-pro, but misspelled parameters are ignored without error, risking silent failures.
Fix: Add speech_model=universal-3-6-pro to the WebSocket URL.

L28 · No parameters v3 silently ignores
The formatted_finals parameter is not recognized by the v3 WebSocket endpoint, so it has no effect on the transcription output.
Fix: Remove the parameter from the WebSocket URL; v3 ignores it.
